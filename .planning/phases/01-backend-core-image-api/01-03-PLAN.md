## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| multipart array upload → multer → batch handler | Up to 20 untrusted binary files enter batch processing simultaneously |
| /tmp/jobs/ paths → fs.rm | Cleanup sweep deletes filesystem paths — path must be confined to /tmp/jobs/ |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | batch file count | mitigate | imageUploadArray = upload.array('files', 20) — multer rejects > 20 files before handler runs |
| T-03-02 | Denial of Service | uncapped batch concurrency | mitigate | pLimit(3) wraps all processImage calls — libvips thread count capped at 3 simultaneous |
| T-03-03 | Denial of Service | archiver memory | mitigate | archive.pipe(res) before any .append() calls — ZIP streams incrementally, never fully buffered; zlib.level:6 not 9 |
| T-03-04 | Tampering | path traversal in cleanup | mitigate | Cleanup sweep only operates on /tmp/jobs/ prefix; fs.readdir + path.join confines deletion to that directory tree |
| T-03-05 | Denial of Service | cleanup sweep crash | mitigate | All fs operations in cleanup.js wrapped in try/catch; sweep errors are logged, never propagated to crash the server |
| T-03-SC | Tampering | npm install (archiver, p-limit) | accept | Both packages verified Approved in Plan 01-01 legitimacy audit; no re-verification needed |
