Sharp pipeline contract (from RESEARCH.md Pattern 2):
  processImage(buffer, options) returns Promise<{ data: Buffer, info: { size, width, height, format }, originalSize: number }>
  options: { quality = 80, format = 'webp', width?, height? }
  MAX_PIXELS = 25_000_000  // decompression bomb guard

  Step 1: await sharp(buffer).metadata() → check meta.width * meta.height > MAX_PIXELS → throw with code 'PROCESSING_ERROR'
  Step 2: let pipeline = sharp(buffer)
  Step 3: if (width || height) pipeline = pipeline.resize(width||null, height||null, { fit: 'inside', withoutEnlargement: true })
  Step 4: switch(format) — jpeg/jpg: .jpeg({ quality, mozjpeg: true }); png: .png({ compressionLevel: 6 }); avif: .avif({ quality, effort: 2 }); webp/default: .webp({ quality })
  Step 5: const { data, info } = await pipeline.toBuffer({ resolveWithObject: true })
  Step 6: return { data, info, originalSize: buffer.length }

Response headers for POST /api/images/process (from RESEARCH.md Pattern 5):
  Content-Type: image/${info.format}
  Content-Disposition: inline; filename="optimized.${info.format}"
  X-Original-Size: req.file.size (bytes)
  X-Result-Size: info.size (bytes)
  X-Reduction-Pct: Math.round((1 - info.size / req.file.size) * 100)
  Content-Length: data.length
  Access-Control-Expose-Headers: X-Original-Size, X-Result-Size, X-Reduction-Pct

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| multipart upload → multer → Sharp | Untrusted binary file content enters the image processing pipeline |
| req.body fields → options parsing | Untrusted query/body values (quality, format, width, height) control Sharp pipeline behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Denial of Service | Sharp pipeline | mitigate | Decompression bomb guard: sharp(buffer).metadata() checks width*height > 25_000_000 before allocating pixel memory; throws PROCESSING_ERROR |
| T-02-02 | Tampering | options parsing (quality, width, height) | mitigate | Convert to Number() before passing to Sharp; Sharp validates internally and throws on invalid values which are caught by try/catch and forwarded to errorHandler |
| T-02-03 | Denial of Service | format=avif batch | mitigate | effort:2 hard-coded for AVIF to prevent minutes-long encode times per Pitfall 4 |
| T-02-04 | Information Disclosure | error responses | accept | Error messages describe the problem but contain no server internals; stack traces are never sent to client |
| T-02-SC | Tampering | npm/sharp install | accept | Package verified in Plan 01-01 legitimacy audit; sharp postinstall script is known-good prebuilt downloader |
</threat_model>
