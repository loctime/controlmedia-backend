**As a** user, **I want to** tweak quality, dimensions, and output format, then re-process the same image as many times as I want and see exactly how much I'm saving, **so that** I can dial in the optimization I need without re-uploading from disk.

  ProcessOptions = { quality?: number; format?: 'jpeg' | 'png' | 'webp' | 'avif'; width?: number; height?: number }
  ProcessResult  = { blob: Blob; contentType: string; originalSize: number | null; resultSize: number | null; reductionPct: number | null }
  FileJob extended in this plan to include:
    originalFile: File          // the raw File from the input, needed for reprocess
    originalDimensions: { width: number; height: number } | null   // from naturalWidth/naturalHeight after the original loads
    blob: Blob | null            // processed blob, used by DownloadButton
    contentType: string | null   // from response.headers['content-type']

hooks/useImageProcessor.ts (from 02-01) currently exposes:
  { job: FileJob | null, process(file: File, options?: ProcessOptions), reset(): void }

This plan extends it with:
  reprocess(options: ProcessOptions): void   // re-POSTs using job.originalFile + new options
  // process(file, options) must now also probe originalDimensions by loading the file into an Image() and reading naturalWidth/naturalHeight before/parallel-with the upload

Backend contract (unchanged from 02-01 / Phase 1):
  Format field values accepted: 'jpeg' | 'png' | 'webp' | 'avif' (NOT 'jpg' — see backend imageProcessor.js switch)
  Quality field: 1–100 string-or-number, server clamps via Sharp
  Width/Height fields: numeric strings; backend uses fit:'inside', withoutEnlargement:true (so passing > original dimensions is safe)
  Response headers (lowercase via axios): x-original-size, x-result-size, x-reduction-pct (all numeric strings; may be NaN if backend omits)

UI format → backend format mapping:
  UI option label "JPG"  → FormData value "jpeg"
  UI option label "PNG"  → FormData value "png"
  UI option label "WebP" → FormData value "webp"
  UI option label "AVIF" → FormData value "avif"

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-controlled option values (quality, width, height, format) → FormData → Render API | Untrusted numeric/string inputs become processing parameters |
| Backend response headers → SizeReadout DOM | Cross-origin numeric headers rendered as text |
| Original File kept in browser memory across reprocesses | Larger memory footprint per session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Tampering | quality / width / height inputs | mitigate | Client-side clamping: quality ∈ [1,100]; width/height ≥ 1; values coerced via Number() before send; backend Sharp validates and rejects with 422 PROCESSING_ERROR if still out of range |
| T-02-02-02 | Tampering | format selector value | mitigate | Select element restricts choices to whitelist 'jpeg' | 'png' | 'webp' | 'avif' — no free-text input; backend default 'webp' if value is somehow missing |
| T-02-02-03 | Information Disclosure | Header NaN leaking into DOM | mitigate | SizeReadout returns null when any of original/result/pct is NaN or null; hook also coerces NaN to null before storing — defense in depth |
| T-02-02-04 | Denial of Service | Object URL accumulation on repeated reprocess | mitigate | reprocess() and reset() both revoke the prior processedUrl before creating a new one; useEffect cleanup revokes originalUrl + processedUrl on unmount |
| T-02-02-05 | Denial of Service | Large original File retained for reprocess | accept | Necessary for IMG-02/IMG-04/IMG-05 UX (no re-pick required). The file already lives in the page's memory from the initial drop; storing the same reference does not duplicate bytes. |
| T-02-02-06 | Tampering | Cross-origin header read failure | accept | Backend already sets Access-Control-Expose-Headers in Phase 1 (verified in 01-02). If misconfigured, SizeReadout simply renders nothing — no false numbers. |
| T-02-02-SC | Tampering | No new npm packages introduced | accept | This plan adds zero new dependencies; only existing 02-01 packages (already audited [OK]) are used |
